# Linux window capture

`LinuxWindowCapture(ulong windowId, int expectedProcessId)` reads one explicitly selected X11 or Xwayland client window into the existing `helengine.media` CPU RGBA surface contract. Supply the actual client window ID carrying `_NET_WM_PID`, its expected process ID, and the target session's explicit `DISPLAY`/`XAUTHORITY` environment. The property is the X11 application's declared PID, not a security attestation.

The implementation requires 64-bit Linux, installed `libX11.so.6`, `libXcomposite.so.1`, XComposite 0.2+, and a TrueColor visual. It names that window's offscreen XComposite pixmap; it never reads a root/screen drawable, enumerates windows, sends input, or changes focus. Native Wayland windows are unsupported. There is no automatic display or capture backend selection. Root windows, absent/mismatched PID properties, unmapped/destroyed windows, resizing and visual changes fail explicitly. Start a new recording after a resize.

`Capture(timestamp, duration)` returns a new owned `MediaVideoFrame`. Pixels are tightly packed top-down RGBA with opaque alpha; 16/24/32-bit native storage, row stride, byte order and TrueColor masks are decoded explicitly. Frames survive later captures and capture disposal. Dispose every returned frame. This is synchronous CPU readback; it makes no hardware acceleration or real-time throughput guarantee. Audio, cursor, decorations and encoder publication are outside this API.

XComposite automatic redirection is registered only for the selected window and released by closing the dedicated Xlib connection. Xlib protocol errors are synchronized and converted to managed failures. Xlib's process-wide error handler is temporarily replaced under a backend-wide lock, forwarding other display connections to the previous handler, including the native default handler. [Xlib's public setter implementation](https://raw.githubusercontent.com/mirror/libX11/master/src/ErrHndlr.c) returns a nonnull previous/default handler; an incompatible implementation is rejected. Applications that independently replace the global Xlib handler must coordinate that replacement with this backend.

Run the test project normally for managed pixel/ownership tests. To include native integration tests, run on an isolated test-owned X server with `DISPLAY`/`XAUTHORITY` set and `HELENGINE_LINUX_CAPTURE_TESTS=1`. Those tests create and destroy only their own small solid-color windows, including an occluding fixture, and check PID failures, geometry changes, unmapped windows and destroyed windows. No test captures the desktop or manipulates another application's window.
